# 课程设计与内容标准（v0.1）

本规范供课程设计 Agent、课程编辑器、交互组件开发者及审稿 Agent 共用。与 `AGENTS.md` 同时生效。

## A. 课程级交付物

每门课建议产生：
- `course.plan.json`：`id`、`title`、`domain`、`level`、`summary`、`prerequisites`、`learningOutcomes`、`chapters` 等；
- 章节依赖图：先修概念、当前章节与后续知识节点；
- 每章一份 MDX，独立交互组件放 `src/components`；
- 关键实验说明（模板见下）与测试；
- 来源、复审与版本记录。技术时效性高的材料需要注明日期。

课程学习目标用可观察行为表达（例如“能够解释为何特征向量反映不改变方向的向量”），不要用空泛的“了解”“熟悉”。

## B. 章节组织模板

1. **开场问题**：以具体困惑、反直觉现象或实际任务提出问题。
2. **现象与预测**：让学习者先做预测，再操作。
3. **第一次实验**：尽早呈现核心交互，操作前明确需要观察什么。
4. **直觉解释**：结合几何形变/算法状态/数据流解释观察到的现象。
5. **形式化**：给出符号、公式和必要推导，检查假设、定义域与维度。
6. **深入一层**：机制、性质、与前置理论的连接。
7. **失败与反例**：边界输入、退化情况、数值误差或常见误区。
8. **应用与迁移**：映射到图形学、AI、机器人或工程问题。
9. **自测**：预测题、概念辨析、一道可实际计算/修改实验验证的练习。
10. **下一站**：告诉学习者学什么，以及为什么是自然的下一步。

章节不要求每一步都占用一个屏幕，结构必须服务知识依赖，而不是机械套用版式。

## C. 交互实验契约

每个核心实验在制作前应具备下列设计信息（可记录在任务/PR 或未来的结构化文件中）：

```yaml
id: matrix-basis-lab
question: "为什么矩阵可以看作基向量被映射到的位置？"
prediction: "只改变第一列时，哪个基向量会改变？网格会怎样？"
controls:
  - "拖动变换后 e₁、e₂ 的端点"
  - "修改 a, b, c, d"
visible_outputs:
  - "变换后的网格和两个基向量"
  - "矩阵、行列式、输入向量的结果"
invariants:
  - "T(0)=0"
  - "T(e₁)=矩阵第一列，T(e₂)=第二列"
edge_cases:
  - "det(A)=0 时面积塌缩"
  - "det(A)<0 时朝向反转（手性改变），注意不等于每个向量都掉头"
test_oracle:
  - "T(2e₁+3e₂)=2T(e₁)+3T(e₂)"
  - "det(A) 与有向面积缩放因子一致"
explanation: "列向量决定基向量去向，线性性决定其余点去向"
```

所有交互控件都需要具备：输入范围/约束、默认状态、重置或预设、文字反馈、坐标和单位约定、至少一个对照状态。更改数据时应通过同一计算模块更新公式与画面。

## D. 深度等级

- **L1 — 观察与直觉**：能描述变化和初步预测。
- **L2 — 公式与实现**：能从假设推导结果，解释算法中关键变量。
- **L3 — 边界与迁移**：能解释反例、局限、计算成本和跨领域用途。

默认课程需包含 L1 与 L2，核心章节尽量达到 L3。提供可展开的深入内容，不强迫初学者一开始阅读全部细节。

## E. 数学、代码与可视化细则

- 提供术语英文对应，但正文以中文自然表达。
- 公式在 MDX 中用 `$...$` 或 `$$...$$` 书写；包含下标、矩阵时实测 KaTeX 渲染，不用截图替代文字公式。
- 矩阵采用明确的行/列约定；坐标系明确左/右手性及轴向；张量标注 shape；概率变量明确随机含义。
- 实验使用可确定的种子或固定例子，给出合法输入范围；极值和退化输入需要解释。
- 避免无依据的“显然”“容易得出”，至少给出关键因果理由。
- 对运行开销、数值精度、训练/推理与仿真/真实部署的区别，避免过度简化。
- 交互无法正确表达的内容宁可使用严谨静态图加推导，也不要生成误导动画。

## F. 课程验收清单（Agent 必须自评）

- [ ] 本节是否有可复述的一句话核心问题？
- [ ] 是否清楚交代知识树的位置及先修知识？
- [ ] 用户能否操作参数并看到因果关系，而非只看自动播放？
- [ ] 是否邀请预测/对比，且反馈解释数学或算法原因？
- [ ] 推导是否检查符号、前提、维度和极端情况？
- [ ] 至少包含一个常见误区/反例？
- [ ] 有明确练习与答案解释，而非仅有结果？
- [ ] 公式渲染、代码类型检查与相关计算单测通过？
- [ ] 已执行交互/响应式检查？未执行时是否明确标注？
- [ ] 是否列出可追溯来源及未核实的版本敏感结论？


## G. 机器可读内容契约

课程元数据的唯一来源是 `course.plan.json`（不是同时维护 `course.json` 与另一份课程计划）。必须通过 `schemas/course-plan.schema.json`。每个 `labIds` 指向 `src/content/labs/<id>.lab.json`，其 `invariants` 与 `edgeCases` 的 `oracleIds` 必须指向已有 `oracles`，各 `testFile` 和 `testName` 必须指向真实测试。规范和可执行校验见 `docs/CONTENT_CONTRACTS.md`。

Schema 能检验字段存在、引用完整和依赖无环，无法从自然语言证明数学正确性；它不替代推导审核和真实交互检验。生成代码不得直接越过 PR 审核进入正式部署。
