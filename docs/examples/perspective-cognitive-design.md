# Cognitive Design 示例：透视校正插值

> 针对已经写过 OpenGL/rasterizer 的非识别性读者角色。现有课程：`src/content/lessons/perspective-correct-interpolation.mdx`。
> 这是**已有课程的认知设计审查**，不是对某位真实学习者掌握程度的测量。

| 设计问题 | 本例决策 |
| --- | --- |
| 已知（假设） | 明白齐次坐标、重心坐标能算出屏幕位置、UV 是顶点属性 |
| 需要确认的盲点 | 是否区分屏幕空间“线性”与三维表面“线性” |
| 本次目标 | 解释为什么屏幕 λ 不能直接插 UV、为什么 `1/w` 修正；可选择推导实现 |
| 核心障碍 | 已经算对 λ，为什么得到错误 UV？ |
| Core Insight | **屏幕上的权重没错，但 UV 需要的是表面位置；两者经透视投影不再成比例。** |

## 最小理解闭环（建议主路径，避免多段术语铺垫）

1. **看见**：相同的三角形三个角对齐、深度没错，但倾斜棋盘格位置不正确。
2. **预测**：远端 `w=3, s=0`，近端 `w=1, s=1`，屏幕中点属性是多少？原直觉答 0.5。
3. **发现冲突**：屏幕中点的三维真实表面属性是 0.75；**错的不是屏幕 λ 的计算，而是其作用空间**。
4. **修正模型**：远处三维距离被压缩。改用 `λ_i/w_i` 并归一化，得到正确权重。
5. **变式迁移**：两端同深度 `w=1` 时，错误和正确方法是否一致？为什么？（会一致，因为除法因子相同。）读者已经可以到此暂停。

无需反复解释 fragment、vertex、4×4 投影矩阵定义；也不为满足媒体指标强制更多滑块。若图明显比数字直观，用正确的三维网格投影图；几何/方向必须独立核验。

## Progressive Disclosure

- **主路径**：真实 Bug + 0.5/0.75 数字矛盾 + 为什么空间变了 + 一次变式预测。
- **原理路径**：`s=(Σλ_i s_i/w_i)/(Σλ_i/w_i)`，由平面方程推 `1/w` 与 `s/w` 的屏幕仿射性；关键公式应显示，不隐藏。
- **边界路径**：深度缓冲的 `z_clip/w` 在屏幕空间可直接插值；细分可减小但不能精确纠错；纹理过滤是另一个问题。

## 体验风险和检查

- **不要**说“正确投影后格子仍是正方形”：真实方格经过透视会变形。
- “屏幕中点 0.5”和“表面中点 0.5”两个 0.5 若含混，会制造新误解；明确它们是不同的点。
- 避免为了形式上的跨学科图谱把这节强连到傅里叶。
- 用户试读反馈与理解迁移**未验证**；已有数学测试和 CI 不能代替此项。

本例的要点不是“每门课必须有一张棋盘图”，而是对懂图形学的学习者，**一个真正反直觉的数字比三段复述重心坐标更有效**。
