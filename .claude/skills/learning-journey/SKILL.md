# Learning Journey — 从问题而不是定义开始

**调用时机**：设计新课程、扩充章节、审查或重写开场、处理“公式清楚但学习不自然”的反馈。

必读：`AGENTS.md`、`docs/LEARNING_DESIGN.md`、`docs/COURSE_STANDARD.md`、`docs/templates/learning-brief.md`。

## 过程

1. 看现有 `course.plan.json`、前后章节与用户已学概念，写明当前知识在树/网中的位置；若上下文不足，列出合理假设而不捏造掌握度。
2. 给出**至少两个真正可用的切入问题**（反直觉、工程任务、几何困惑等），比较哪一个更直接推动核心理论；避免“一上来定义 X”。
3. 为首选问题写`现有解释的不足 → 认知转折 → 新思想解决了什么 → 局限/反例 → 回到问题`的自然叙事线，注明每个公式在何时必要。
4. 设计关键知识连接（先修/对比/应用），解释“相同点与不同点”，参考 `knowledge-map`。
5. 决定哪些地方需要文字、静态图、分步图、交互或不需要图。**不得强制每节安排动画**。需图时进一步读取 `visual-research`。
6. 写 `docs/templates/learning-brief.md` 形式的教学设计工件，然后再写课程。既有章节改造时，保留已经正确的公式、代码和测试，只调整教学动机和需要补充的解释。
7. 课程完成后，先隐藏交互读叙事，再隐藏故事读数学，分别审核（与 `course-review` 配合）。

## 拒绝条件

- 新概念出现之前没有足够的“为什么此时需要它”。
- “问题”只是定义前面的装饰句，后文没有回扣。
- 图片或动画先于概念目标被决定，或内容必须靠动画才可读。
- 只追求趣味，牺牲结论成立条件；为故事编造真实发现历史。

## 输出

`Learning Brief`（内部设计稿）+ 课程叙事摘要（3 句）+ 需要保留/补充的证明与反例 + 媒介需求 + 待验证事项。必要时同步更新 `course.plan.json`，但不要改动 schema 不支持的字段。
