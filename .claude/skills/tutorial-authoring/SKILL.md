# Tutorial Authoring — 机制本身就是讲解

**优先入口**：用户要求编写/生成课程、重写原理教程，或反馈“像教科书、抓不住核心”时运行本 Skill。局部图形修复/知识映射可单独调用专项 Skill。不要让若干专项 Skill 各自独立生成一篇课。

先读：
- [已验证与失败的两个案例](references/cases.md)：不是模仿排版，而是学习成功与失败是怎么产生的。
- [验收与返工协议](references/review.md)：负责阻断严重教学问题、真实页面检查、报告。
- [跨主题评估任务](evals/cases.json)：用于定期回归，不是每次自动批量生成。
- 项目约束：\`AGENTS.md\`、\`docs/CURRICULUM_CONTRACT.md\`、\`docs/TEACHING_STYLE_BASELINE.md\`、\`docs/COURSE_STANDARD.md\`。

## 唯一的北极星

**读者读完后，能否不复述公式，也讲清本主题最难的 1–3 个“为什么”，并预测一个未展示的情况？**

不要把“有理论、有插图、有单测、有交互、完成课程文档”当作教学成功。数学验证只能支持正确性，不能证明教学质量；自评不能替代真实读者反馈。

Anatomy 的“object is the explanation”在这里被转译为 **mechanism is the explanation**。高质量教程的核心不是装饰精致的图，而是**因果链有证据、难点被解释、读者能沿着走下去**。

## 按顺序制作；每个 Gate 不通过就停下修正

### Gate A — 先选对要解释的机制（写正文前）

1. **归属与范围**：检索课程树与已有文章，明确用户到底问的是什么。**不能把标题扩大成整学科综述，也不能把局部亮点偷偷换成主问题**。主题依赖紧密时优先一篇完整文章。
2. **最终理解产物**：不写“了解协方差”“掌握 Diffusion”；写一条能够验证的因果说明，例如“局部投影导数为何导致特定的二维足迹”。
3. **机制链草图**：用 3–7 条真实因果关系把输入→关键中间量→输出串起来，标记最重要的 1–3 个断点。**不超过一段的学术历史、术语定义或边界不配占据中心**。
4. **反向质询**：把标题遮住只看草图，能否从这条机制复原原问题？若不能，或最生动的反例占据了主干而关键过程仍未解释，**退回选题定位**。不要开始画图或做交互。
5. **阅读基准**：阅读对应的正/负参考案例。读者背景只供内部裁剪解释深度，正式正文不得出现“你已经知道……”。

最小内部产物：一段真正的问题、一条机制链、每个关键断点的解释策略；可记到已有 \`learning-brief.md\`，**不要新建一堆表单或在页面暴露这些字段**。复杂新课可用 \`learning-journey\`、\`knowledge-map\` 进一步规划。

### Gate B — 先让讲解成立，再增加表现形式

6. **写一篇可从头读到尾的“裸稿”**：先用日常技术语言准确解释关键因果，文字中的每个转折都来自上一个步骤没解释完的疑问。核心推理不能被放到仅可展开的附录；非关键代数可以。
7. **逐段做因果回放**：遇到关键结论，检查是否已有具体输入、处理机制、输出变化、假设与限制。像 3DGS 的“投影椭圆→每像素 Gaussian 权重→Alpha 合成”少一步就必须补。每当把一句“本质上/显然/因此”替换成真正的计算或状态变化，讲授质量才可能提高。
8. **给关键原理选最轻的图**：一张图只为回答特定难题。优先准确静态图/分步图、真实数据或可复算的数值图；必要时选实物照片与来源。**没有核心图示也讲不明白的机制不能靠文字堆砌**；简单关系无需独立实验。参考 \`diagram-authoring\` 和 \`visual-research\`。
9. **事实先于画面**：像 Anatomy 用同一个物理模型驱动读数，KnowledgeLab 必须让图中坐标、时间、顺序、方向、数值来自明确公式/算法。无法数值验证的示意要显著标为“示意”；概念图不伪装成真实训练/渲染效果。即使同源，也针对**箭头方向、前后顺序、遮挡与说明**进行独立语义核验。
10. **刻意删减**：逐条问“删掉这个例子、图、滑块或小节，关键理解会丢失什么？”若回答不出就删。必要时将边界与长证明折叠，交互只在静态媒介无法胜任时加入。

### Gate C — 在实际页面上像挑剔读者一样审查

11. **看到真实页面**：运行项目；在桌面、390px 手机视口截图整篇及每个关键图，打开图片逐张检查，尤其是符号、标注、剪裁、遮挡与数学语义。推荐 \`node scripts/capture-lesson.mjs http://127.0.0.1:5173/courses/... --out .tutorial-review/<topic>\`。**仅有元素断言、构建和 CI 不能算视觉审查**。
12. **脱离作者 Brief 重读**：按 [验收与返工协议](references/review.md) 从零阅读最终文章，不看作者“为什么这样设计”的解释。先检查主问题有没有回答，机制是否闭环、复杂重点是否被例子淹没；然后才检查语句是否自然。
13. **独立技术审查**：公式前提、坐标/单位、统计与近似、图示绘制顺序，和原始论文/标准核对；采用相互独立的 oracle/反例测试。负责写图的 Agent 不能只给自己图形代码的 DOM 断言就说“正确”。
14. **返工优先于粉饰**：任何 P0（关键机制遗漏、核心图误导、主题偏离）先**改机制链和图**，而不是继续增添解释或润色词句。局部 P1/P2 再调整段落、标注与布局。作者自检可提交 \`prototype\`，**不能自行标 \`reviewed\`**。
15. **报告实际覆盖**：记录具体 URL、截图路径、人工看过的图、计算对照、CI、已知缺陷与真实读者反馈状态；没看截图就写“未执行视觉审查”。保留已有 Course 状态约束；遵守用户分支/提交要求。

## 审稿角色

- **作者**负责证据和完整可读主线。
- **教学批评者**首先质疑“文章是否解释了应该解释的问题”，**不能**只检查 Brief 勾选项；最好新上下文/独立 Agent 阅读成稿。若无法独立调用，诚实标记“作者自检”，不要假称独立审稿。
- **数学与图示审稿者**优先寻找反例、画错的轴/方向/时序与公式适用条件。
- **真实学习者**的理解与评分仍然是唯一能验证该读者体验的证据之一，不得从自动 CI 推断。

## 使用已有专项 Skill，不重造轮子

- \`learning-journey\`：需要设计认知链或重大结构调整时。
- \`knowledge-map\`：课程体系/先修关系发生变化时。
- \`visual-research\`：需要外部事实或图片时。
- \`diagram-authoring\`：需要精确 SVG、可验证图示时。
- \`course-review\`：依据本 Skill 的 Gate C 做独立内容与技术审查。

**交付物**：一个可连续阅读的最终教程、必要的高价值图及计算、只记录有信息量的审查证据；而不是规范文件数量、图片数量或测试数量的增长。
