# KnowledgeLab 教学设计原则 — 从问题到知识网络

> 本文件是 **Agent 的课程编辑标准**，不是网站展示给学习者的固定栏目模板。
> 适用于新的课程以及旧课程改版；与 `AGENTS.md`、`COURSE_STANDARD.md` 同时生效。**先读 `docs/LEARNING_EXPERIENCE_CONTRACT.md` 明确目标读者的已知/假设、最小理解闭环与深入层，再用本文组织知识叙事。**

## 1. 我们拒绝什么

- **教科书搬家**：标题是概念名称，开篇定义，紧接公式、推导，末尾匆匆放一个应用。
- **假问题**：把“为什么要理解 X？”当开场，下一段立刻给 X 的定义；问题没有驱动学习路径。
- **强行故事化**：与概念无关的冗长日常故事，只为吸引注意，不支撑解释。
- **动画即课程**：先选漂亮可视化，再找概念来匹配。
- **知识孤岛**：讲完只知道本节结论，不知道它依赖什么、替代什么、连接什么。
- **错误的探索史**：为了叙事编造“科学家当年就是这样发现的”；复现思考路线不等于宣称历史事实。
- **过度简化**：讲直觉却不回到条件、数学证明、运行机制和局限。

## 2. 教学目标：动机、理解、连接、迁移

一节成熟课程必须帮助学习者回答：

| 维度 | 学习者的问题 | 作者必须给出的证据 |
| --- | --- | --- |
| Motivation | **为什么**这里需要一个新工具/概念？ | 原问题、已有办法的不足，或有张力的反直觉现象 |
| Understanding | 它**如何工作，为什么成立**？ | 因果链、可预测的心智模型，必要时严格推导 |
| Connection | 这位于**知识网络的哪里**？ | 先修、相邻/对比概念、联系本质以及跨领域例子 |
| Transfer | 我学完究竟**多了什么能力**？ | 回答开场问题、解释陌生情境或解决变式任务 |

**先理解现象再出现公式**是常用手段，不是强制死序。当公式本身是问题时可直接讨论它；但必须交代为什么关心这个公式。不要为了追求故事感牺牲精度。

## 3. 从知识目录变成探索路径

对新课程、改变课程主线的重大改稿，或新增跨章节知识连接，作者在写 MDX 前应先完成 `docs/templates/learning-brief.md`，至少明确：

1. **真实的问题**：一个可感觉到的限制、疑惑、冲突或待解决任务，不必一定来自生活。
2. **读者原有模型**：已有知识能解释到哪里？会在哪一步失效？
3. **认知转折（aha）**：换一个视角后，哪些零散现象被同一个思想解释？
4. **渐进机制**：每引入一个新概念/公式，指出“此刻为什么需要它”。
5. **回扣问题**：最初的问题现在如何被解决？新理论又暴露哪些边界？
6. **连接网络**：至少一个有因果解释的先修连接、一个可迁移连接；不得只列标签。

这份 Brief 是内部设计工具，不是每次改动都要提交的公开课程文件。局部修正、测试修复和视觉/实现调整只需确认没有破坏已有叙事；若已有 Brief，优先更新它而不是另起一份。章节级 Brief 只在该章节有独立认知转折或改变课程主线时创建。

**不强制按上述顺序分六节**。允许先反例、先实验、先工程任务或先一张图；叙事的每一步必须有因果理由。结构像一条学习旅程，不像百科词条。

### 好开场与坏开场

| 知识 | 不要这样开场 | 更好的问题 |
| --- | --- | --- |
| 傅里叶 | “定义周期方波 f(t)=...” | “相同音高的两种乐器，为何音色不同？如何看见复杂声音里包含的简单振动？” |
| PCA | “给定协方差矩阵，求特征向量” | “点云沿斜方向延伸，分别看 x/y 方差为什么捕捉不到最主要的变化？” |
| Vulkan | “Command Buffer 是记录命令的数据结构” | “OpenGL 帮你隐去了哪些 CPU/GPU 调度成本？为什么 Vulkan 必须让你显式记录提交？” |
| VAE / Diffusion | “VAE 优化 ELBO，Diffusion 学习噪声” | “如果只会辨认真实图片，如何从随机数出发构造一张新图片？两条路线各学到了什么？” |

这些只是**设计备选**：所用事实、类比和历史来源须单独核实，不能因为例子吸引人就省略必要条件。

## 4. 以“可运行的心智模型”解释

- 数学：变换什么、什么保持不变、坐标系和几何对象如何关联；先让读者预测，再严格说明。
- 计算机系统：状态、内存、数据流、调用边界、并行执行、成本；解释实现与抽象之间的映射。
- AI：训练数据、张量形状、优化目标、训练与推理两条运行链、近似和失败模式。
- 机器人：观察、动作、环境状态、奖励或专家标签、rollout、仿真到现实的差距。

每当读者可能产生“虽然认识术语，但不知道系统下一步会发生什么”的困惑，优先补**过程图/状态图/小例子**，而不是重复定义。

## 5. 知识网络比树更重要

课程既要标记**位置**，也要写出**关系及理由**。

最低要求：
- 上游：本节用到的先修概念及**使用到哪一部分**；
- 同层：至少一个相关、对比、特例或一般化关系及其边界；
- 下游：可以使用当前知识解决的一类新任务；
- 跨领域：确有真实映射才写，不强凑。

建议关系词：`prerequisite`（前置）、`derives-from`（推导自）、`generalizes`（推广）、`contrasts-with`（区别）、`same-principle`（共同机制）、`applied-in`（应用）、`misconception-of`（容易混淆）。

现有 `course.plan.json` 中 `knowledgeNodes.dependsOn` 是**局部先修依赖图**，不应把所有“应用、比较、类比”都错误地塞进它。Course Contract v2 将其余关系记录在课程目录的 `knowledge-map.json`（端点、类型、理由、边界）；`knowledge-map.md` 只解释教学桥梁。校验器支持跨课程端点和全局先修环检查，但尚无知识网络页面或推荐系统。

**一个好的连接要说明“同在哪里、不同在哪里”**。例：PCA 取协方差最大特征值对应的主方向，而局部点云平面法线取最小特征值对应方向：共用协方差与特征分解，但目标不同。

## 6. 图示、交互与文字的取舍

根据**待解释的认知困难**选择媒介：

| 要回答的问题 | 通常优先 |
| --- | --- |
| 几个对象的组成/相对位置？ | 标注清晰的静态图 |
| 一段过程中的因果与状态？ | 流程图、分步图、时序图 |
| 改变变量会怎样？ | 有预测反馈的交互，或成对对照静态图 |
| 某个严格结论为什么成立？ | 逐步数学推导，必要处补几何图 |
| 真实物体/场景长什么样？ | 权威来源的可合法使用照片或原创示意 |
| 某个抽象空间如何变化？ | SVG/Canvas/WebGL；确有需要时才上 3D |

没有交互并不减分；没有帮助理解的图也不必强加。若使用图片，必须遵守 `docs/VISUAL_ASSETS.md`。

## 7. 学习效果验收（独立于 CI）

审稿人先**不看动画、不看公式细节**，只读段落标题和开头结尾：

- 能不能用 3 句话说清“从哪个问题来 → 为什么引入概念 → 回到什么问题”？
- 每个新术语出现时，前文是否已经创造了需要它的情境？
- 公式是为了解决问题而推出来的，还是忽然被塞进来？
- 有没有原知识与新知识冲突时的桥梁说明？
- 学完能不能用新思想预测或解释一个**不同于讲过例子**的情境？
- 图片/动画是不是让读者更理解，不是只为了丰富页面？
- 是否既足够自然，又维持必要的证明、定义和适用条件？

任何一项关键问题回答不了，课程不得仅凭 Schema/CI 通过就宣称“内容已审核”。

## 8. 反教材味不是反严谨

教材式“先定义后定理”在某些证明课可能恰当。这里反对的是**没有动机的公式堆砌和无意义的固定模板**。要在学习动机成熟的地方交付同等甚至更严谨的推导。

> 判断标准：即使删除全部交互，正文仍应是一条清楚的发现与解释路径；即使删除故事，引理与计算也必须独立正确。
