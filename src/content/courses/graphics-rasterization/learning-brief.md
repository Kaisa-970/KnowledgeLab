# Learning Brief：光栅化——透视校正插值

> 这则笔记的设计依据。定位是**原理笔记**，不是教程：目标是让读者理解机制为什么成立，不承担教会读者写代码的责任。针对有图形学实践、但底层为什么这么做说不清的人，不针对第一次接触三维图形的人。

## 体裁：为什么去掉实现细节

第一版草稿里有一整节 C++ 代码、一节自测题、以及"症状 → 几何 → 原理 → 矛盾 → 代码 → 自测 → 回扣"七个小节。阅读反馈是"割裂"、"下一段突然换方向"。

诊断：**七个并排的小节不是一条思路。** 每次换标题，读者要重新定位；而"回到 C++"是从原理跳到工程，切断了正在建立的因果链。修改后只保留一条推理线：

三个角的值已知 → 中间该取多少？→ 面积加权的自然规则 → 它错在"屏幕不是曲面的等比缩放" → 屏幕上有没有真正线性的量 → 1/w 与 s/w → 这个式子实际在说什么 → 深度为什么不受影响。

实现细节、自测题、跨课程迁移全部移除。

## 为什么从这一句问起

核心问题只有一句：**三个角上的值已知，三角形内部每一点该取多少？** 所有内容都从这一句推出来，不引入管线阶段、不罗列术语。

这个提问方式的好处是它自带一个看似正确的答案——按屏幕面积加权，也就是三角形中点取三个数的平均。这个答案容易接受，而且**只是微妙地错**：错在把"屏幕上的面积比例"当成了"曲面上的面积比例"。整则笔记的作用就是把这一点拆开。

## 读者原有模型，以及它在哪一步失效

| 读者已有的认识 | 在本节哪一步失效 |
| --- | --- |
| 顶点属性在三角形内"按重心坐标线性插值" | 重心坐标是在**屏幕**上算的，而属性是**视空间**线性的。两个空间不成比例，所以权重不能直接用 |
| 屏幕上的一半就是空间中的一半 | 只有两个端点深度相等时才成立。一般情况屏幕中点对应 $t=w_a/(w_a+w_b)$ |
| 深度测试和纹理走同一套插值，所以要么都对要么都错 | 深度存的是 $z/w$，它本来就是屏幕空间仿射的，所以**只有它不受影响**。这不是矛盾，是两条不同的量 |

## 认知转折

**"屏幕空间均匀"和"视空间均匀"是两个不同的均匀。** 一旦意识到 $1/w$ 才是那个真正在屏幕上均匀变化的量，整件事就闭合了：$1/w$ 与 $s/w$ 都是屏幕空间的仿射函数，因此都能用屏幕权重精确重建，相除即得 $s$。

这个转折的特殊价值在于它是**可当场验算的**，不需要相信。这里的 Lab 把它做成两张并排的棋盘格：同一个三角形，同一个格点分解，只是权重来源不同，形状差异直接可见。

## 媒介选择

| 教学单元 | 选择 | 理由 |
| --- | --- | --- |
| 错误的权重规则 | 纯文字，先说对再指出错 | 读者要先接受这个诱人的错误答案，才有动机看修正 |
| 面积比例的错位 | 文字 + 棋盘格的想象 | 这是全部症结所在，用一个可以自己想象的场景说清 |
| 平面方程推导 | 行间公式（不折叠） | 三行，且是唯一的正式推导，藏起来反而断链 |
| 两种权重的对比 | 并排两个 SVG 面板 | 差异是空间形状，必须**看见**；用动画反而看不出"哪里歪" |
| 深度为何不受影响 | 纯文字 | 这是一个反直觉的解释，画图是噪音 |

**刻意没有做**：C++/GLSL 代码、自测题、三维拖动视角。代码会让原理笔记变成教程；三维视角只增加操作负担，而错误在屏幕平面内已能看全。

## 图示的取舍（一轮返工）

并排面板的第一版把三角形按 26×26 细分填色，比棋盘格本身还密，形变被碎成噪点，两张图看起来一样。第二版改成网格线，位移只有 0.45 格，肉眼仍抓不到。第三版确定为 12 格棋盘，并把默认深度差从 1.35 倍提到 **2.2 倍**（`DEFAULT_SPREAD = 1.2`），此时左图呈斜条纹、右图呈均匀方格，差异一眼可见。

这个默认值由测量确定，不由审美确定：测试断言默认夹具的位移必须超过一个格宽，否则面板就白画了。

## 正确性依据

`src/math/perspective.ts` 里的两条插值路径签名完全相同，差异只有一处除法。所有断言都指向数值测试，而不是文字说明：

- 校正路径与视空间参考值一致到浮点精度（网格采样，非仅顶点）
- $1/w$ 的仿射性由平面方程**独立解出**再比对，不依赖插值代码本身
- 深度用朴素插值精确，用以支撑"纹理歪但深度对"这个论断
- 深度差为 0 时两条路径完全一致，用以支撑"简单测试测不出这个 bug"
