# Diagram Authoring — 图本身是一段可核验的解释

必读：`docs/VISUAL_ASSETS.md`、`docs/LEARNING_DESIGN.md`、相关 `math` 源码与 `Visual Brief`。

## 流程

1. 提炼一个图要回答的具体问题，并列出正确性约束（轴向、单位、坐标、状态/时间顺序、输入输出、几何不变量）。
2. 选简单、可复用的技术：静态 SVG/React SVG 首选，复杂数据用确定性绘图脚本，必要时 Canvas/WebGL；无数学需求的示意才考虑非精确生成图。
3. **计算与绘图分离**：数值由数学模块或参考算法产生，不在渲染层另写另一套公式；为关键变换准备解析解、性质或独立参考测试。
4. 避免仿制他人有独创性的图形表达；基于公共事实和独立布局原创设计，明确“示意”与“实际测量”。
5. 布局检查：视觉层次、方向、图例、轴、单位、色盲友好、手机阅读、适当 alt 和说明；动画需有状态反馈与减少运动偏好。
6. 若设计交互，写控件→状态→可见结果→不变量与边界；用 Playwright 操作，不把“能点击”当作“理解正确”。
7. 若工具暂不可用，提供明确的设计稿/源码建议并标注未渲染检查，禁止声称完成。

## 检查清单

- 图的**教学任务**不是“显得专业”；
- 显示数值/箭头符合模型，不能遮掩边界或反例；
- 放大缩小和移动端仍可读；
- 数据、随机种子、公式、授权与 alt 可追溯；
- 不使用生成模型绘制精确坐标系、真实测量结果或数学定理证明图。

## 输出

可编辑图源、可见用途描述、caption/alt、核验方法与实际测试结果、未验收项。
