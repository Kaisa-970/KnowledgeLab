
# Learning Brief：透视校正插值（技术博客体裁）

> 面向已经使用过 OpenGL、理解齐次坐标、屏幕重心坐标和 UV 的读者。只补“理解断层”，不从零讲光栅化。状态保持 prototype。

## 核心矛盾

自己写软件光栅化器时：三个顶点对齐，深度缓冲结果也正常，但棋盘纹理沿深度方向发生形变。程序员看起来“没有错”的操作，是直接将**屏幕重心权重**拿来混合**三维表面属性**。

第一屏就给“错误路径 vs 真实曲面投影”图，图必须在几何意义上正确：

- 正确路径：先在三维表面按 barycentric 确定真实格子位置，再投影到屏幕。**真实方格在透视投影后也会变形，近大远小**。
- 错误路径：将同一个表面参数直接用于屏幕三角形中的线性坐标，格子在屏幕上分布太均匀。
- 对应网格点与三个顶点一致；内部坐标一般不同。对照必须使用同一三维表面与同一参数网格。

## 一个足以说清楚的数字

沿一条远近深度比为 3:1 的边，屏幕中点的原始重心权重各为 1/2。远端属性 0，近端属性 1。

- 直接插值 -> 0.5（错误）。
- 用 1/w 归一化 -> 近端权重 0.75（真实属性）。
- 在真实三维边中点增设正确位置、正确属性的新顶点后，朴素分段插值得 2/3；细分能减少误差但不是精确校正。

数字之后再推导：1/w 与 s/w 为屏幕空间仿射量，两个都插值再相除。

## 知识连接与边界

- 先修只使用投影除法与重心坐标，不大段复述 GPU 流水线。
- 深度插值必须清楚指出 **z_clip / w** 而不是含混的“z/w”：深度可屏幕线性插值，并不意味着视空间 z 也可以。
- 若进一步问纹理闪烁，指出其属于采样/过滤而非插值位置，是自然下篇入口。
- 不为知识网络关联数量强行引入傅里叶级数；已删除无事实基础的“细分三角形完全无效”关系。

## 媒介选择

- 主线文章按“实际 Bug → 算得出来的反例 → 一条核心公式 → 为什么成立 → 深度之谜”推进。
- Lab 放在开篇，直接观察错误和正确图；示意图可以解释重心不同，但不强迫大量术语或自测。
- 严格证明保留在正文的主要步骤；次要代数展开按需展开。
- 数学数值/投影位置由原始 math 模块校验；视觉语义单独审查，不把“两个图的点有差别”当作“正确的图已经画对”。

## 审核提示

人工再次体验：右侧是否明显呈真实透视的近大远小（而非“格子保持正方形”）？简洁文章能否在前两屏理解 Bug？对不熟悉图形学的人不补基础，本课明确属于 intermediate。


## Learning Experience Check（设计，非学习效果测量）

- **确认已知**：无针对具体读者的实际答题证据。**目标读者假设**：有 OpenGL/软件光栅化基础，理解重心坐标、UV、透视除法。
- **当前卡点**：屏幕 λ 正确却不能直接用于表面 UV；旧模型混淆“屏幕线性”和“三维表面线性”。
- **Core Insight**：屏幕权重没错，错的是用来插值的空间。
- **Minimal Loop**：相同三角形的纹理错位 → 预测屏幕中点 UV=0.5 → 远端 w=3、近端 w=1 的真实属性为 0.75 → 用 1/w 解释差异 → **变式**：同深度 w=1 时两法是否一样（一样）。
- **主路径**：Bug、0.5/0.75 反例、必要的透视修正公式；**深入**：1/w 的平面推导、深度为何特殊；**边界**：细分与纹理过滤的区别。
- **压力风险**：不重复教授重心算法或图形管线基础，不连续堆多个坐标空间符号；“正确贴图”的格子也会透视变形，不能描述为屏幕正方形。
- **自然退出点**：能解释为什么需要透视校正并预测等深度退化情形。**实际读者迁移表现未验证**。
