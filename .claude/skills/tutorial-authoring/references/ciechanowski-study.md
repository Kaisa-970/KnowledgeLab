# 从现象到可见机制：Ciechanowski 的教程制作方法

> 观察来源：[Cameras and Lenses](https://ciechanow.ski/cameras-and-lenses/)、[Curves and Surfaces](https://ciechanow.ski/curves-and-surfaces/)、[Airfoil](https://ciechanow.ski/airfoil/)、[Gears](https://ciechanow.ski/gears/)。分析的是公开文章的**叙事构造与图示功能**，并非原作者公开的制作流程，也不是复刻其动画、图形代码或风格资产。此参考不代表本站新课程已经获得学习者的效果验证。

## 关键发现：先构造读者能够观察的东西，再引入数学和抽象

文章不是“定义 → 定理 → 配图 → 小结”的顺序，也不总是“先抛一个反例再修复”；更准确的是：

**可见对象/现象 → 一个读者能辨认的变化或困难 → 只引入解释该变化所必需的机制 → 改变观察方式以暴露下一层关系 → 必要时用数学精确化。**

不要把这条分析简写成“必须有互动、必须有失败案例、必须采用某个固定五步模板”。不同题材采取不同路径。

### 例 1：Cameras and Lenses——让失败的简化模型证明新机制的必要性

原文路径（[直接阅读](https://ciechanow.ski/cameras-and-lenses/)）：

1. 先让光子照在传感器上，建立**光信号 → 像素亮度**的直观对应；颜色滤镜与 demosaicing 在这个对应基础上逐步出现。
2. 把裸露的传感器放进真实场景；读者看到的图片**没有可辨认的结构**。原因不是算法不够先进，而是每个像素都接收来自太多方向的光。
3. 只添加一个新构件：黑盒上的小孔。它限制每个像素能接收的方向，于是有了针孔成像。
4. 针孔变小使图更清楚，也使照片变暗；**这次改善产生了新代价**。把锐度与进光量这两个变量分开看到后，引入会聚光线的镜头才有意义。
5. 文章讲透对应光路及约束，才逐渐讨论参数和公式。关键角色是读者可以在**同一个相机系统**中比较改动前后，而不是每段换一个无关的卡片。

迁移判断：如果有一个**真实存在且可观察**的朴素方案不足，可以先展现其缺陷，再引入唯一必要的修正。禁止为了“冲突感”捏造一个没人会采用的错误算法；“25 倍足迹反例”不能替代 3DGS 核心投影机制的介绍。

### 例 2：Curves and Surfaces——先建立可见权重，再出现公式

原文路径（[直接阅读](https://ciechanow.ski/curves-and-surfaces/)）：

1. 先展示控制点移动，曲线在不同位置发生多大变化。
2. 用颜色标示**某个控制点对各位置的影响**，不是只展示“曲线变了”。
3. 从两点连成的直线开始：移动虚拟画笔可以连续展示位置权重由 A 转移到 B。
4. 读者已有这个几何含义后，才写 \(P=(1-t)A+tB\)。从直线延伸到曲面时仍然使用相同的控制点与参数思路。

迁移判断：先找出公式每一项在图上**对应什么可观察的量或变化**。如果公式中的 \(\Sigma\)、\(J\)、\(J^T\) 没有在图上对应“点的偏移、局部投影导数、两次乘积变换”，只画一个“椭球变椭圆”的最终结果还不够。

### 例 3：Airfoil——看不见的机制，要借助多个互补视角

原文路径（[直接阅读](https://ciechanow.ski/airfoil/)）：

1. 风本身不可见，先通过草叶倾斜**间接观察局部速度**。
2. 用固定位置的箭头编码某处、某时刻的流速与方向（欧拉视角）。
3. 换成随流而动的标记点和轨迹，展示一团流体**沿时间经历了什么**（拉格朗日视角）。
4. 再用颜色只表示速度大小，并明确说明这种表达会**失去方向信息**；需要时可以叠加箭头。

迁移判断：同一原理往往需要两个或三个真正不同的视角，例如**单个粒子的轨迹 vs 整体分布**、**局部数值 vs 全局变化**、**3D 世界坐标 vs 屏幕像素**。不能拿几种颜色/排版重复同一个信息来冒充多视角图。

### 例 4：Gears——先观察运动约束，再推导参数关系

原文路径（[直接阅读](https://ciechanow.ski/gears/)）：

1. 从一片旋转圆盘开始，比较同角速度下不同半径的点走过的弧长。
2. 得到 \(v=\omega r\) 的具体几何含义。
3. 放入第二片接触圆盘，指出无滑动接触时**接触点的切向线速度相同**；只有此时才推导两侧角速度与半径比。
4. 然后才引出转矩这一新问题；不是把齿轮、转矩、传动比放成并列术语清单。

迁移判断：如果可以从一个**明确的不变量或约束**推导公式，就先看约束再写公式。

## 为 KnowledgeLab 提取的可执行动作

选择讲解方案时，在草稿里找出本篇最重要的因果缺口，并优先考虑以下**可任选的方法**：

- **建造并比较**：先给一个最简可工作的对象/过程；若存在真实缺陷，让读者比较增添一项机制前后发生了什么。
- **让中间量可见**：图不只画输入、输出，还要揭示看不见却决定结果的状态、权重、光路、梯度、速度或内存依赖。
- **同一对象逐层显影**：尽可能复用同一示例、颜色编码和坐标约定，将它从直觉图带入数值图再带到公式。确需换例子，先交代什么保持不变。
- **主动区分互补视角**：单个状态 / 群体分布，固定位置的场 / 沿场运动的粒子，整体物体 / 局部细节。每个视角都要回答一个不同的问题。
- **让公式与可观察的对象接上**：可以先从图或现象归纳规律，再用公式精确表达；也可以先提出公式，再用图、数值或推导看清它揭示的关系。无论顺序如何，都要说明符号对应什么、公式支持什么预测或解释，避免符号悬空。
- **呈现简化模型的代价**：固定了哪些参数、忽略了什么现象、何时需要更复杂模型，避免把玩具演示假装成精确物理模拟。

### 需要“交互”吗？按辨别任务决定

| 需要观察什么 | 优先表达 | 不必强制操作 |
| --- | --- | --- |
| 单次几何关系、矩阵变换结果、前后两状态对比 | 有标注的静态图、并排对照 | 不必强制 |
| 参数连续变化才能看清趋势或临界条件 | 少量可调参数的交互图、连续帧序列 | 交互可选，静态基准仍须可读 |
| 轨迹、时间依赖、视角相关的歧义 | 控制时间/视角的动画或同物体多视角图 | 动画必须能暂停，有明确观察任务 |
| 局部行为难以理解全局规律 | 局部视角与全局视角并排，保持对象/数值一致 | 控件必须提供额外信息 |

**不要为了模仿 Ciechanowski，把所有原理强行制作成复杂交互场景。** 它的作品确实大量使用交互，但我们的用户此前已明确反对装饰性的滑块和实验。

## 针对 3DGS 6 分失败案例的具体转译

不要继续围绕“25 倍足迹反例”增加几张测试图。可以在原来的**同一颗三维高斯**上逐层显影：

1. 在 3D 中显示以均值为中心的等密度面和三个轴向尺度；明确它是高斯的等值面，不是实心体。
2. 投到相机屏幕，并画出一个小偏移 \(\delta x\) 在透视作用下对应的 \(\delta p\)；让 Jacobian 是这个**局部映射**，而不只是符号。
3. 从映射前后一组偏移样本的散布解释 \(\Sigma_{2D}\approx J W\Sigma_{3D}W^TJ^T\)，明确它属于一阶近似。
4. 在同一个二维分布里标出中心像素与边缘像素，展示指数权重怎样不同；如果文章承诺解释最终图像，再展示沿**正确深度顺序**的 Alpha 合成。
5. 把超大的深度向方差、近裁剪和线性化失败当作**模型适用边界的补充**，而不是用局部反例代替主链。

这不是强制所有 3DGS 课程扩展到完整 rasterizer：**文章标题承诺了什么，机制链就覆盖到什么**。不要以测试中列出更多环节作为扩展内容的理由。

## 一次审核的三个对照问题

1. 读者在每一步看到了什么具体改变？最重要的中间量是否显影，而不只是“箭头指向结果”？
2. 当文章引入一个新术语、公式或模型时，之前的观察是否已经使其有必要、有意义？是不是为了覆盖术语清单而硬插？
3. 不做任何点击与拖动，读者仍能否从静态状态、文字、数字和关键公式理解核心机制？如果不能，交互是否真的不可替代，或应提供一组有说明的静态快照？
