# Roadmap — 以教学质量而非功能数量推进

## P0（本次初始化）：项目契约与完整教学切片

- [x] 产品定位与 Agent 规则
- [x] 课程设计模板与生成/验证工作流
- [x] Vite + React + TS + MDX 基础站点
- [x] 一节《矩阵与线性变换》的互动示例
- [x] 纯数学计算的单元测试与 CI 配置
- [ ] 浏览器真实交互、移动端与视觉验收
- [ ] 部署地址（尚未配置任何托管）

**门槛**：完整课程可阅读，改变矩阵会改变网格与数值；数学计算与构建可验证。

## P1：可复用交互知识体系

- [ ] 固化课程元数据 Schema、课程索引与知识依赖关系
- [ ] 基础绘图组件：坐标系、向量、投影、二维变换、函数曲线、状态步骤
- [ ] 实验统一接口：输入、输出、状态、预设、校验、重置
- [ ] 2–3 节可复用实验课程：矩阵 → 特征向量 → PCA
- [ ] 浏览器 E2E 测试，公式快照与基础无障碍检查

**门槛**：同一个交互模块在至少两节课程中复用，不降低解释质量。

## P2：Agent 辅助生成（需人类审核）

- [ ] 从自然语言生成课程规划与 Lab Contract
- [ ] 生成 MDX/TSX/测试的最小工具调用链
- [ ] 受限隔离环境运行构建、测试和视觉检查
- [ ] 自动提交 PR，由人审核后合并
- [ ] 失败报告驱动局部修复，不盲目重写全部内容

**门槛**：用户提出主题后，Agent 生成一节新的完整课程，通过可审计测试与人工审核。

## P3：长期产品

- [ ] 学科知识网络与个性化先修路径
- [ ] AI 基于当前实验状态答疑与章节局部扩充
- [ ] Three.js/WebGPU 实验、代码运行沙箱、机器人仿真可视化
- [ ] 学习进度与用户账号（确有需求时）
- [ ] 多章节自动规划与审校、持续知识维护

## 评价指标

- 用户能否解释关键不变量/失效条件；
- 交互前后预测正确率或可复述能力是否改善；
- 每节课有意义的实验比例；
- 数学验证与交互测试覆盖率；
- Agent 生成课程一次通过率与人工修订量。

不以课程数量、动画数量作为主要 KPI。


## Phase 0.5 — 课程协议/数据驱动架构

- [x] 定义课程计划 Schema、实验 Lab Schema、验证器
- [x] 验证器失败样例：缺字段、断裂引用、未知 oracle 与依赖环
- [x] 课程目录构建时发现，不再手改 `App.tsx` 添加章节
- [x] 加入 Playwright 桌面/移动交互测试与 CI 执行流程
- [ ] 独立内容审校与实际学习效果评测（仍需要人工过程）
- [ ] 隔离 Agent 运行环境（接入自动生成之前必须完成）
- [ ] 第二门课程验证协议扩展性（建议傅里叶级数）

**验收解释**：构建通过 ≠ 交互通过 ≠ 数学/教学内容审查通过。可执行的质量门禁详见 `docs/CONTENT_CONTRACTS.md`。


## Phase 0.6 — 教学叙事、知识网络与可追溯视觉素材规范

- [x] 明确“问题/困惑 → 认知转折 → 严格论证 → 回扣/迁移”，避免定义堆叠和死板模板；
- [x] 定义知识关系类型，区分 `dependsOn` 的先修关系与对比、共同原理、应用关系；
- [x] 建立权威资料研究与图片版权独立核验流程；
- [x] 建立学习叙事、知识定位、素材检索、原创绘图与审查 Skills；
- [ ] 用上述规范改写现有傅里叶课程的开场与整体叙事，并修正独立数学审查发现的问题；
- [ ] 设计人工或半自动的叙事/理解成效审核（不能只靠 Schema 证明）；
- [ ] 选择适合平台的工具运行环境，让 Agent 能真正调用检索、绘图与受限浏览器；
- [ ] 评估多课程知识网络结构化字段是否值得在下一版 Schema 中增加。

**约束说明**：`.claude/skills/*.md` 为文本指引，不代表自动生产管线已实现；旧课程的数值/教学问题不因本次文档修改而自动消失。
