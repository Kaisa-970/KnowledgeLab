# KnowledgeLab 教学风格基线 v1 · 从 8.5/10 长文中提炼

> **默认用于今后新增和重大改写的技术学习文章**。这是经过实际读者反馈校准的**起点**，不是统一题材模板、排版配方或保证高分的证书。用户后续对具体文章的反馈优先，基线应继续迭代。

## 基准作品与反馈证据

- **当前参考作品**：[《从一团噪声到一张图，生成模型究竟学会了什么？》](../src/content/lessons/generative-from-noise-to-image.mdx)，Course \`generative-models\`，Chapter \`from-noise-to-image\`，对应版本至少包含提交 \`b886a5ea6f19c95eb1edcb6b23d0f965b03bb3ed\` 的解释和原理图。
- **真实主观反馈**：初版 **2/10**（问题引入薄弱、近乎没有关键图，像教科书）；分章节配图版 **5/10**（有进步但割裂且文字模板化）；合成长文版 **7.5/10**（连续性好，但重点仍不突出、反向采样等机制跳步，并出现“你知道……”）；补足关键因果解释和可计算图后的当前版本 **8.5/10**。仅反映一位学习者对该具体版本的评价，不代表独立数学审核或其他课程必然同分。
- 这篇文章是**写作/讲授方法的参考**，不是固定的 Diffusion 章节结构。线性代数、Vulkan、机器人学习等主题应围绕各自最难的机制组织。

## 应当保留的做法

**1. 整个主题围绕一个值得追问的问题。** 不从“X 是什么”的术语目录开场，也不靠长故事制造动机。优先找真实的输入、输出、现象或工程矛盾，最好在开头几十秒内显出解释价值。进入第二个概念的理由必须来自第一个概念尚未解决的困难。

**2. 用一条不中断的因果线写，必要时一篇讲完。** Track / Module / Course / Concept 是**知识组织层级**，不等于网页篇数；相互依赖的原理优先放在一篇自然连贯的技术文章里。只有先修条件、任务目标或题材边界确实不同才拆篇。小标题帮助浏览，不替代过渡。

**3. 把笔墨花在最难的“为什么”。** 真实基线里，不仅说明“噪声网络预测 ε”，还进一步解释：
   - 同一带噪输入可能有不同来源，为什么 MSE 的最优预测是**条件均值**；
   - 条件噪声预测为什么与带噪分布的 **score** 相联；
   - 学到局部规律之后，**怎样构造一步反向转移**，再如何保证整批样本的分布演化；
   - 训练配对路径的速度标签与生成时的**平均速度场**为什么不是同一个对象、为什么后者能推动正确的边缘分布。
   
   **关键认知桥梁缺失，比语言不够口语更严重。** 对其他主题也要先找出类似的 1–3 个核心跳步，补足输入→计算→中间状态→输出之间的机制。

**4. 重要原理用正确且有用途的图。** 对空间结构、状态转移、分布演化、算法数据流，优先考虑一张准确的静态图或分步图。图需回答一个具体认知障碍，说明变化量、固定量、符号/坐标/时间方向；优先可计算、可核验的示例，不画“看起来对”的轨迹。标注**概念示意、解析数据、真实实验**三者区别。无论有几张图，都不能让示意误导机制。图的数量不作为指标。

**5. 公式出现在“非它不可”的位置。** 先使量与过程有含义，再用公式确定关系；不能省略决定结论成立的步骤。决定理解的公式放在正文，完整代数、严格条件或实现边界可按需展开，但不能藏起核心结论。

**6. 文字像懂技术的作者，不像教案或 AI 提示词。** 句子直接、具体，句间有逻辑延续；允许自然提出疑问，但不要段段用反问推进。**学习者画像只用于内部选材与深度，不写“你已经知道/你应该懂/按照你的基础”**，也不在正文罗列“本节目标、现在你掌握了、核心洞察、下一节学习什么”。删除没有推进理解的总结、机械口头禅和重复强调。尽量减少强调格式，让真正的重点自然突出。

**7. 交互必须证明自己比静态图更有帮助。** 一眼就懂的关系不用滑块；分步图足够便不用动画。确有价值的实验作为可选深入，且图形与计算同源、有独立数值依据。没有交互不是缺项。

## 每次创作的默认内部次序

1. **归属**：查全局知识树与已有文章，先决定是解释、修已有文章，还是需要全新内容。
2. **难点**：写下本篇读者最可能误会的因果环节，按重要性排序；剔除已经具备的基础。
3. **讲解草稿**：先写一条可一口气读完的叙事主线，逐段检查“为什么从上一段走到了下一段”。
4. **证据/图**：只为关键难点选择最轻媒介；先核实几何/数学/运行时语义，再把图自然融进文字。
5. **精确化**：补核心公式、关键条件与必要证明；深入材料不要阻塞主路径。
6. **编辑盲审**：脱离目录/教程模板，连续朗读正文，删掉硬转场、陈词滥调、已知基础与不必要实验；检查读者能否说清最关键的 1–3 个机制。
7. **独立校验**：数学与图示测试、CI、人工讲授审查和真实读者评分分别报告；一项通过不替代另一项。

这一过程**不能自动转成七个页面栏目**，也不要求每个话题七步俱全。

## 改稿优先级与演进

当读者觉得“不懂”或“还像教材”，依次诊断：
- **机制是否跳步**：知道结果，却解释不出“为什么能从 A 到 B”？优先补因果桥梁与反例。
- **主次是否颠倒**：太多笔墨花在基础、边缘术语和形式化指标？删去，突出主问题。
- **图是否承担解释**：能否单看图理解关键变化；图是否数学上准确？
- **语言是否顺畅**：去掉对学习者背景的宣告、公式前后的生硬引入、重复反问及样板式总结。
- **章节是否割裂**：是否应合并为同一篇；实验是否可选。

**不要把打分变成硬性机器发布阈值。** 当前基准来自真实单人反馈；以后按主题收集具体卡点与更高质量例子，更新本文件的适用边界与版本。始终保留 \`prototype\` 与独立审查的区别。
