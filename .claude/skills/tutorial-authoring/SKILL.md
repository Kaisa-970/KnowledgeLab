# Tutorial Authoring — 先把最难的一步讲清楚

**优先入口**：用户要求编写/生成课程、重写原理教程，或反馈"像教科书、抓不住核心"时运行本 Skill。局部图形修复/知识映射可单独调用专项 Skill。不要让若干专项 Skill 各自独立生成一篇课。

**制作时先读** [局部讲解的制作示范](references/explanation-workshop.md)：从跳步原稿到可计算解释，再检验一个新情况。

**挑选图文结构时参考** [从现象到可见机制：Ciechanowski 案例](references/ciechanowski-study.md)：学习如何把一个最小对象逐步演化、让不可见的中间量显影、借互补视角解释复杂机制。**不是复制交互形式，静态图足够就不用控件。**

按任务需要读取：
- [真实改稿历史](references/walkthrough.md)：用于理解生成模型文章的取舍，不把评分归因当作实验结论。
- [正反案例](references/cases.md)：用于范围和主次校准。
- [验收协议](references/review.md)：成稿审核时读。
- [跨主题 evals](evals/cases.json)：评估 Skill 的迁移能力时读，不是每次创作都要运行的清单。

项目约束见 `AGENTS.md`、`docs/CURRICULUM_CONTRACT.md`、`docs/LEARNING_EXPERIENCE_CONTRACT.md` 与 `docs/COURSE_STANDARD.md`。

## 唯一的北极星

**读者读完后，能否不复述公式，也讲清本主题最难的 1–3 个"为什么"，并预测一个未展示的情况？**

不要把"有理论、有插图、有单测、有交互、完成课程文档、检查器全绿"当作教学成功。数学验证与渲染检查只能排除错误，不能证明教学质量；自评不能替代真实读者反馈。

**先找出读者必须相信、却还无法解释的那一步，再选择证据。** 证据可以是一组具体数字、一段执行过程、短推导或一幅图。增加篇幅、公式、图片和检查器都不能自动补上这一步。原理解释与清晰文案共同影响阅读，不从一次评分变化推断各自的独立贡献。

## 按顺序制作；每个 Gate 不通过就停下修正

### Gate A — 先选对要解释的机制（写正文前）

1. **归属与范围**：检索课程树与已有文章，明确用户到底问的是什么。**不能把标题扩大成整学科综述，也不能把局部亮点偷偷换成主问题**。主题依赖紧密时优先一篇完整文章。
2. **最终理解产物**：不写"了解协方差""掌握 Diffusion"；写一条能够验证的因果说明，例如"局部投影导数为何导致特定的二维足迹"。
3. **机制链草图**：用 足够串起主问题的真实因果关系把输入→关键中间量→输出串起来，标记最重要的 1–3 个断点。只保留帮助回答当前问题的历史、定义和边界。
4. **反向质询**：把标题遮住只看草图，能否从这条机制复原原问题？若不能，或最生动的反例占据了主干而关键过程仍未解释，**退回选题定位**。不要开始画图或做交互。
5. **选择解释策略**：参考 `references/explanation-workshop.md` 的最小因果证据，以及 `references/ciechanowski-study.md` 的**最小对象→真实困难→新增机制、同一对象逐层显影、互补视角**。这些是按需要选择的创作策略，绝不是强制的文章分节模板。读者背景只供内部裁剪解释深度，正式正文不得出现"你已经知道……"。

最小内部产物：一段真正的问题、一条机制链、每个关键断点的解释策略；记到已有 `learning-brief.md`，**不要新建一堆表单或在页面暴露这些字段**。

### Gate B — 先让讲解成立，再增加表现形式

6. **先试做最难的片段**：先写出一段读者能独立读懂的解释，包括必要上下文、关键机制、最小算例或执行链；需要图时先做简图。暂不铺开全部章节，也不先精修画面。具体示范见 `references/explanation-workshop.md`。
7. **早期检验，再扩展**：只依据片段回答“为什么成立”和一个未展示的变式，指出答案依据。独立审稿者找出只能相信公式的地方；有读者反馈时记录原话与卡点，没有则标记“作者自检，理解未验证”。修复缺口后扩展为连续正文。不要为了等可选反馈停下全部工作；可继续核验事实、算例和先修关系。读者自然追问是寻找缺口的线索，不要求每个下一段必须回答它，更不把正文写成连续问答。
8. **给关键原理选最轻的图**：一张图只为回答特定难题。优先准确静态图、可复算的数值图。**先让决定输出的中间量可见**，必要时保留同一对象、颜色与坐标，借图展示一次改动的前后区别；若使用多个视角，明确各自新增的信息。只有连续参数、时间或视角改变确实促进理解时才交互，且提供静态可读的关键状态。
9. **事实先于画面**：图中坐标、时间、顺序、方向、数值必须来自明确公式/算法。无法数值验证的示意要显著标为"示意"；概念图不伪装成真实训练/渲染效果。
10. **刻意删减**：逐条问"删掉这个例子、图、滑块或小节，关键理解会丢失什么？"若回答不出就删。
    **新模型必须有理由**：引入每个术语、额外参数或推导时，指出此前观察还无法解释的现象；若只是让文章更复杂，删除或转为按需深入。不要为了制造认知冲突而故意设计一个不存在的错误模型。

### Gate C — 在真实页面上像挑剔读者一样审查

11. **跑检查器**（便宜，先跑）：
    ```bash
    npm run audit:figures   # 也包含在 npm run validate 里
    ```
    这是源码级提示，不会运行或渲染组件。`risk` 需核实，`manual` 需结合实际页面判断；两者都不是自动失败，也不是视觉审核的完整清单。报告需逐项记录处理结果；零提示不代表零缺陷。
12. **看到真实页面**：桌面、390px 手机视口截图整篇及每个关键图，**打开图片逐张检查**，尤其是符号、标注、剪裁、遮挡与数学语义。用 `node scripts/capture-lesson.mjs <url> --out .tutorial-review/<topic>`。**仅有元素断言、构建、CI 和检查器全绿都不能算视觉审查。**
13. **脱离作者 Brief 重读**：从零阅读最终文章，不看作者"为什么这样设计"的解释。先检查主问题有没有回答、机制是否闭环；然后才检查语句是否自然。
14. **独立技术审查**：公式前提、坐标/单位、统计与近似、图示绘制顺序，与原始论文/标准核对；采用相互独立的 oracle/反例测试。负责写图的 Agent 不能只给自己图形代码的 DOM 断言就说"正确"。
15. **返工优先于粉饰**：任何 P0（关键机制遗漏、核心图误导、主题偏离）先**改机制链和图**，而不是继续增添解释或润色词句。
16. **报告实际覆盖**：记录具体 URL、截图路径、人工看过的图、计算对照、CI、已知缺陷与真实读者反馈状态；没看截图就写"未执行视觉审查"。

## 技术工具的职责

关键数学与算法放在 `src/math/*` 的纯函数中，图和数值读数复用它们；坐标映射、路径拼接、布局留在绘图层。核验实际传入的参数、坐标约定和排序，不能把“调用了已测函数”当成整个图正确。

`scripts/audit-figures.mjs` 仅提示源码中的可疑字号、非有限常量、混合计算重复和路径生成器。它不证明裁切、运行时数值、曲线形状或领域语义正确。作用域、CSS、变换及运行时数据可能使静态估算失效；以实际渲染和独立计算复核。检查器的植入缺陷与正常对照在 `scripts/audit-figures.test.mjs`，修改后执行 `npm test`。

不为“主问题被回答”“因果闭环”“读者理解”制作词汇/栏目数量代理检查器。特定图的方向、时序等性质若能形式化，可以写领域测试，仍需实际读图。

## 审稿角色

- **作者**负责证据和完整可读主线。
- **教学批评者**首先质疑"文章是否解释了应该解释的问题"，**不能**只检查 Brief 勾选项；最好新上下文/独立 Agent 阅读成稿。若无法独立调用，诚实标记"作者自检"。
- **数学与图示审稿者**优先寻找反例、画错的轴/方向/时序与公式适用条件。
- **真实学习者**的理解与评分是唯一能验证该读者体验的证据，不得从自动 CI 推断。

## 评估任务的两层

`evals/cases.json` 里每条分两部分，**不要合并**：

- **技术评估**：可执行检查、明确性质、错误对照。可以写成命令与零容忍项。
- **教学评估**：只依据成稿能否解释关键机制、预测未展示的变式、以及这些答案的依据在正文哪里。Agent 可以评估正文是否提供足够依据，实际学习效果由读者回答验证。

只有真实读者的回答才能支持"确实形成了理解"。

## 使用已有专项 Skill，不重造轮子

- `learning-journey`：需要设计认知链或重大结构调整时。
- `knowledge-map`：课程体系/先修关系发生变化时。
- `visual-research`：需要外部事实或图片时。
- `diagram-authoring`：需要精确 SVG、可验证图示时。
- `course-review`：依据本 Skill 的 Gate C 做独立内容与技术审查。

**交付物**：一个可连续阅读的最终教程、必要的高价值图及计算、检查器与截图证据、只记录有信息量的审查证据——**而不是规范文件数量、图片数量或测试数量的增长**。
