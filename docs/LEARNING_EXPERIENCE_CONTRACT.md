# Learning Experience Contract — 从“写好课程”到“帮助人理解”

> **适用范围**：新课程、课程主线改造，以及学习者反馈“看不下去 / 太像教材 / 仍然不理解”时的重新设计。
> 与 Course Contract v2 **并行**：v2 管引用、数值、审核与发布状态；本文件管理认知设计和学习效果。它是 Agent 与内容审稿人的**人工可检查契约**，不是新的 JSON Schema、自动测量学习效果的系统或固定页面模板。

**默认讲授基线**：`docs/TEACHING_STYLE_BASELINE.md`，参考现有单篇生成模型长文；它固定经 8.5/10 实际反馈校准的写作方法，不固定故事结构与媒介数量。新任务若有更明确的学习者反馈，以新反馈为准。

## 核心目标

Agent 的默认任务**不是完整地讲完一个主题**，而是：

> 识别当前学习者已有的模型及其障碍，设计最短的可信理解路径；先让人建立能预测、能解释的新模型，再根据需要深入证明、实现和边界。

**阅读负担最小化，不是知识降级。** 一句精确的因果解释、一个真正有用的反例、一张正确的图，比多段定义更重要。过于基础的知识点可跳过或用链接唤醒，不重复教学；有深度的推导不能被删除，只是由认知需要决定位置。

## 1. Learner State：学习者不是“初级/中级/高级”标签

在写主线前，区分四类信息：

| 类型 | 例子 | 处理方式 |
| --- | --- | --- |
| **确认已掌握** | 学习者解释过重心坐标的计算方式 | 直接利用，不再写一节重心坐标入门 |
| **可能掌握** | 做过 OpenGL，但未确认理解非仿射的透视除法 | 标记为*假设*，用一句桥接或一个轻量检查，不声称已经掌握 |
| **当前卡点** | 会算 λ，却不明白为什么 λ 不能直接插值 UV | 本节围绕这一具体矛盾，不重写整个渲染管线 |
| **本次目标与情境** | 想快速理解原因，还是要自己实现 rasterizer | 决定停在哪一层以及是否需要代码细节 |

学习者模型按**概念与本次任务**建，不按头衔判定数学或工程理解。没有可信信息时可采用“目标读者暂假设具备 X”的短声明；必要时通过一个问题校准，不为了画像收集冗长问卷。

**隐私与边界**：课程仓库原则上保存**非识别性的目标读者能力假设**，不公开个人对话、健康、家庭、身份等信息；具体用户学习状态由获授权的私人上下文提供，不得伪称已存储、已自动追踪或已经测出掌握度。用户纠正时以其反馈为准。

## 2. Cognitive Gap：找一个真正的理解缺口

设计时先写四句（内部工件，**不作为正文标题**）：

- **已有模型**：学习者本来如何解释这个现象？
- **冲突/缺口**：这个模型在什么可计算、可观察或可执行的情境下给错预测？
- **Core Insight**：学完后，他能用一句自己的话作出什么**新的因果解释**？
- **最短证据**：一个反例、过程、数值、几何示意、实际实验或逻辑证明，怎样让这句解释有说服力？

优先一个主障碍；不是“一节只许一个术语”。多个新概念若缺少它们就无法解释当前冲突，可自然连起来；但每次上下文跳转必须有用途。无真实冲突时不要制造假 Bug、假历史或夸张故事，直接说清要解决的任务。

## 3. Minimal Understanding Loop：先建立一个可运行的心智模型

一个最小闭环应让学习者可以：

1. **看见或设想**一个足够具体的输入和现象；
2. 在答案前有机会**预测**结果（可以只是读者心中预测；不强制按钮/问答）；
3. 对比实际结果或一个清楚的反例，发现原模型不足；
4. 借一个必要的新思想解释**为什么**会出现该结果；
5. 在**一个未直接演示的变化**上再次预测，并能检查理由。

可以用一张图、几行计算、表格或完整交互。**不是所有知识点都必须有滑块、动画或显式五段结构**。如果一句因果解释加一个数字反例足以达成目标，就到此为止。

主路径提供一个**自然退出点**：学习者到这里已经能解释 X、预测 Y，不需要读完附加章节才算“学到东西”。这应在文章行文中自然呈现，禁止每段都插“你已经掌握了”之类打断阅读的口号。

**局部闭环仍要连接领域主线**：解决当前问题后，用简短自然的衔接说明它在领域中的位置、还缺哪块关键理解，以及下一步为什么值得学。不要求新增栏目或罗列完整知识清单，避免系统学习退化为彼此孤立的短解释。

## 4. Cognitive Load：预算的是切换成本，不是理论难度

- **一段主线只解决一个主要问题**：第一次引入的数学对象、状态变量、坐标空间、时间尺度不能同时无缘无故换掉。
- **一个新公式有一个明确的工作**：出场前已有问题需要它；旁边说清它在输入、输出和约束之间建立了什么关系。关键公式本身可以直接呈现，**不能一律折叠**。
- **优先复用已知概念**：熟悉矩阵/向量投影的人不必重学点积定义；可以直接说“把向量换成函数、点积换成积分”，再深入讨论差别。
- **消除冗余**：删除“首先、然后、总结”等为结构而写的重复解释；连续几个相似比喻只保留最准确的一个。
- **过程图优先于术语堆**：如果卡点在执行或状态变化，展示“输入 → 中间状态 → 输出”比再解释定义有用。
- **数学深度不设低上限**：当读者选择 Derive / Implement 时，可以给出完整证明、边界和代码；不要为了“轻松”牺牲条件与反例。

设计时在 Brief 标出**压力风险**：最容易堵住阅读的陌生符号、上下文切换、旧知识复习、证明细节。决定它们是主线必需、简短桥接、延后还是可选展开。

## 阅读单元的粒度和连续性

一门 Course 下有多个 Concept，不代表必须按节点生成多个网页。训练、生成、数学机制如属于同一条因果链，优先写成可以一口气读完的高质量技术文章；只有不同先修或独立任务才合理拆分。把内部设计分层直接映射成固定栏目，会制造教科书感。

技术作者的好文案让新问题从刚解释的现象自然生长出来，而不是反复说“本节要理解什么、现在你学会了什么”。利用读者已有经验跳过基础，但不跳过精确机制。优先静态原理图；没有充分理由，不添加交互实验。

## 5. Progressive Disclosure：三层能力，不是固定 5/15/30 分钟

| 层级 | 能获得什么 | 默认处理 |
| --- | --- | --- |
| **Understand · 主路径** | 解释现象、指出旧模型的失败处、作一次正确预测 | 默认可直接完成；直觉与关键因果不能藏掉 |
| **Derive / Implement · 原理路径** | 推导公式、跟踪状态与张量、实现关键步骤 | 在需要的位置自然衔接；非关键的代数细节和实现可展开 |
| **Transfer / Boundary · 迁移与边界** | 新条件下重新预测，指出反例和适用条件 | 一个关键迁移尽量靠近主路径，其余深入按需 |

“按需”不意味着全部用 `<details>`，也不意味着强制显示三个栏目。连续写作仍可像优秀的技术博客自然推进。对已经熟练的读者，可以直接从第二层的反直觉问题入手；对基础不足的读者，提供简短的前置知识链接。

**退出权**：完成主路径后就能形成准确但有限的认知模型；不懂完整证明不等于“一无所知”。独立数学审查仍必须覆盖正式发表的正确性主张。

## 6. 体验审查：与工程 CI 独立

新课或重大改稿在提交前要有**具体证据**，不只是填 `completed`：

| 体验问题 | 可接受证据 |
| --- | --- |
| 能不能快速进入问题？ | 读首屏时已经看到矛盾/实用任务，先修概念没有大段重复 |
| 读者预设是否合理？ | 已知/假设/未知的区分；跳过的基础明确但可回看 |
| 直觉能不能形成？ | 一个小例子能解释输入改变为什么改变输出 |
| 主线是否过载？ | 一次主要认知转折；跳步、概念突变、冗长重复被改掉 |
| 理论是否被恰当放置？ | 关键公式连接当前问题；深入证明可找得到且条件完整 |
| 真正理解了吗？ | 未演示的变式能够预测，答案含机制解释而不是术语复述 |
| 能停下来了吗？ | 主线独立成立，有自然退出点，深入路径不挡前路 |

没有真实学习者反馈时，只能报告**“作者设计检查通过 / 用户理解尚未验证”**。不能把 Agent 自评、浏览器测试或文件存在等同于真实理解。阅读反馈优先修正教学设计，不优先堆更多内容或动画。若反馈指出“原理还是没讲清楚”，优先寻找**关键因果断点**，补上从监督目标到中间机制、再到实际运行结果的推理，不要只做句式口语化。

## 7. Agent 执行次序（内部，不是课程目录模板）

`学习需求 → 判断已知/未知和本次目标 → 定位主要认知障碍 → 找最短可核验例子 → 写主路径 → 加原理/边界分支 → 做迁移预测 → 数学/视觉/内容独立审核`。

新建课程或重大叙事重构，应在既有 `learning-brief.md` 内记录上述决策；局部修复只修改受影响的决策和验证范围。**不增加 schema 字段，不强制每个自然段、每节课另存六份文件。**

详见 `docs/examples/perspective-cognitive-design.md`、`docs/examples/vae-diffusion-cognitive-design.md`。前者关联现有可运行课程，后者只是未来生成模型课程的设计示例；不能冒充完成的课程或已验证的学习效果。
