# 最终页面的验收与返工协议

这份清单用于**独立审稿者直接阅读成稿**，不是作者把 Learning Brief 改写成评分报告。不要把下列栏目变成正文结构，也不要给未试读的文章自动打分。

## 第一遍：遮住“作者意图”，只看最终文章

1. 在不看 brief/plan 的情况下，**一句话写出正文到底回答了哪个问题**，再与用户原题对照。若正文回答的是“漂亮反例”而非用户真正关心的机制，**P0：重构文章**。
2. 不查外部材料，仅凭正文复述**因果链**：输入是什么→发生了什么关键变化→如何计算/推导→为什么产生输出。记录读到哪一步开始只能“相信公式”或“相信图的箭头”。这些点是必要桥梁，不靠新增术语清单解决。任何直接影响主问题的缺口为 **P0**。
3. 去掉非核心细节，检查文章是否仍可成立；若主问题只在结尾几个句子得到解释，大篇幅却在证明一个少见的特殊例子，为 **P1**（严重时 P0：整篇范围跑偏）。
4. 技术作者口吻：上下文自然接续，没有“你已经知道”“接下来你会掌握”、连续反问、反复总结、强制读者操作。此项 **P1/P2**，不能替代机制检查。

## 第二遍：屏幕内容、数学与认知任务要一致

5. **真实查看截图**：本地运行 Vite，使用 `scripts/capture-lesson.mjs` 输出桌面、390px 移动视口、每个解释性图局部 PNG。打开并查看图片（必要时放大），不能只查看脚本输出。检查正文图出现的位置、图注是否够独立、字号、裁切、遮挡、公式换行、显示顺序与色彩编码。
6. **图像语义审计**：对每张核心图列出一条可复述命题、一个最可能误读点、数值/几何依据。尤其需要独立检查深度顺序、正负号、时间方向、坐标约定、前/后景混合和模型边界；数学共用同一函数也不能保证图标注正确。
7. **技术事实**：原始论文/文档核实变化敏感的主张；核心算法的性质、参数极限、维度/单位、独立实现或解析 oracle。统计采样必须标明 seed/样本数/边界；概念示意不得当真实实验图。
8. **媒介反事实**：若删掉某图或某控件，核心理解会丢失什么？没有明确答案的交互删去或降为选读；没有明确答案的装饰图删除。不设“每篇必须有几张图”的指标。

## 源码提示与实际审核分开记录

`npm run audit:figures` 不渲染组件。它用语法树提示可疑字号、显式非有限常量、混合计算重复及路径生成器；不会核验真实裁切、CSS/变换、计算产生的 NaN/Infinity、数值一致性或坐标语义。risk 为需核实的风险，manual 为需读图的提示；零提示也不代表视觉通过。

在已有 course-review 中记录每条提示的结论和依据（修复、合理用途、待核验），以及实际打开的截图范围。不需要为了提示新增一套报告。源码检查成功只说明扫描完成；未核验项仍须诚实保留。

修改检查器时运行 `npm test`，既验证植入缺陷能被提示，也验证正常代码不误报。领域性质如混合顺序、射线方向可有独立测试，但任何单一检查都不能代替成稿阅读和真实试读。

## 检查关键解释片段

全文扩展前，参考 [制作示范](explanation-workshop.md)，只依据片段解释“为什么成立”并预测新情况。标出哪一步只能相信作者。审稿者回答成功证明的是正文存在依据；真实读者能否理解仍单独记录。

## 必须阻断 / 可以迭代

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| P0 核心问题与机制 | 标题承诺完整 rasterizer，却缺少像素权重链；核心因果跳步 | **退回 Gate A/B**，不能靠加一句总结修复 |
| P0 数学/图误导 | front-to-back 却按远→近累积；符号或时间方向错误 | 改公式/源模型/图，增加不同路径的回归用例 |
| P0 审核状态虚报 | 没有打开截图却声称人工验收；作者自检标独立审稿 | 纠正报告，保持 prototype；必须补真实审核才升级 |
| P1 重点和媒体 | 边界反例比核心内容长、强制无意义实验 | 重新分配篇幅、删除无效组件 |
| P2 文字呈现 | 过多“本节/下一节”“你知道”等模板话术 | 最后再改句子，不用润色掩盖主干缺陷 |

## 可执行检查（有工具时）

```bash
npm run validate        # 含源码提示
npm run audit:figures   # 单独跑源码提示
npm run typecheck
npm test
npm run build
npm run test:e2e

# 单独终端启动服务后截真实页面。
npm run dev -- --host 127.0.0.1 --port 5173
node scripts/capture-lesson.mjs http://127.0.0.1:5173/courses/<course-id>/<chapter-id> --out .tutorial-review/topic
```

`capture-lesson.mjs` 输出全页、逐图与横向溢出/控制台异常日志。输出路径在 gitignore 中；这些文件不是学习效果证明，**审稿者必须真的查看**。浏览器不可用则明确记录“未执行逐图视觉审核”，不能把 DOM 测试冒充截图审核。

## 简短报告约定

把检查证据写进已有 `course-review.md` 即可：
- **用户题目 vs 成稿实际问题**、3 条最关键因果关系、正文行/图定位。
- **具体 P0/P1/P2 问题**（没有问题才写无，不能靠作者承诺），及修复动作。
- **截图路径与已打开阅读的范围**、独立公式对照与真正执行的测试。
- **角色诚实声明**：作者自检 / 不同上下文审稿 / 真人反馈；`prototype` / `reviewed` 分级遵循既有契约。

不需要引入新的 10 页报告模板。若一轮生成需要大量 governance 文件才能完成，Skill 自身就值得精简。
