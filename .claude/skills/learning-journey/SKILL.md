# Learning Journey — 从问题而不是定义开始

**调用时机**：设计新课程、改变课程主线的重大改稿、新增跨章节知识连接、审查或重写开场、处理“公式清楚但学习不自然”的反馈。局部修正、测试修复和纯视觉/实现调整通常复用已有设计，不必重新生成整套 Brief。

必读：`AGENTS.md`、**`docs/LEARNING_EXPERIENCE_CONTRACT.md`**、`docs/LEARNING_DESIGN.md`、`docs/COURSE_STANDARD.md`、`docs/templates/learning-brief.md`。

## 过程

1. **Learner State**：从已有真实反馈/当前问题判断确认已知、可能已知、当前卡点和目标深度。没有信息则标注非识别性假设，不造假，更不把个人私密资料写进公开课程库。
2. **Cognitive Gap**：优先找一个主要理解障碍。可从反直觉 Bug、算法执行、数学变换或真实疑问切入，不强制列两个故事；对已有基础跳过重复定义。
3. **Minimal Loop**：设计“观察/具体输入 → 预测 → 反例或结果 → Core Insight → 新条件再预测”的**最短可检查闭环**。不强制按钮、动画或任何固定页面栏目。
4. **Main Path**：先写短主路径并安排自然退出点。**关键公式出现在解决问题的时刻**；非关键证明和深入实现放按需路径，不删除严谨前提。
5. **Pressure Risks**：识别突然引入的陌生符号、切换的上下文、过长的基础回顾、重复比喻；优先减少主线压力，再决定图/交互。
6. **Knowledge links**：只加真正帮助本次理解的先修、对比和迁移链接，并解释边界；需要时使用 `knowledge-map`，制作图时依视觉规范。
7. **Review**：有一个未直接演示的变式问题与明确因果答案；读者不展开所有深入内容也能形成正确模型。最后数学、内容与视觉独立审核；没有真人反馈只能写“理解未验证”。

只有新课程、重大改稿或关键认知转折变化需要完整更新 Learning Brief。局部修复只记录受影响范围，**不增加模板填写量**。

## 写成一篇文章还是拆分多节

先尝试一条连贯的文章主线，依一个问题自然引出下一个问题。分篇必须说明独立先修、阅读任务或讨论边界；不能以概念节点数量、交付物 Schema 的字段数来决定篇数。通过**连续通读**检查文案是否像真实作者在讲解；不要用“本节/下一节/学完你会”填充过渡。图先解释难点，交互不是默认教学媒介。

## 拒绝条件

- 新概念出现之前没有足够的“为什么此时需要它”。
- “问题”只是定义前面的装饰句，后文没有回扣。
- 图片或动画先于概念目标被决定，或内容必须靠动画才可读。
- 只追求趣味，牺牲结论成立条件；为故事编造真实发现历史。
- 对熟悉的基础概念大篇幅重复，或把完整知识清单一次塞进主路径。
- 以 Agent 自评、CI 通过代替学习者实际解释与迁移证据。

## 输出

既有 `learning-brief.md` 中的**非识别性已知/假设、认知障碍、Core Insight、最小闭环、主/深入路径、压力风险、可解释的迁移问题及未验证项**。不要在正式课程里照抄这些字段。课程叙事可以是一篇连贯的优秀技术博客。
